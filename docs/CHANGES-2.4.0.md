# CellCoal 2.4.0 — what changed

**Without the new options the simulated data of all existing runs are identical to 2.3.0.**

## New: realistic amplification, reads and a chromosome in blocks
- `--ado-block L`, `--ado-origin O`, `--ado-seed S` (also `ado_block`, `ado_origin`, `ado_seed` in a configuration file): allelic dropout in contiguous segments (a two-state chain per allele and cell, lost segments of mean length L sites, same mean ADO as `-D`/`-P`). The segments continue across the pieces of a chromosome (`--ado-origin`, `--ado-seed`); `tools/chrom.py` passes them. Default data are unchanged. See manual 8.24.
- `--signature-file FILE` (also `signature_file` in a configuration file): 96-context signature profiles in COSMIC format used by `-S` instead of the 30 built-in ones. `data/signatures/` has COSMIC v3.6 SBS1 + SBS5 and the PTA artifact signature of SCAN2. Default data are unchanged. See manual 8.25.
- `--amp-signature FILE` (also `amp_signature` in a configuration file; needs `-C` and `-A`): the amplification error depends on the trinucleotide context and its substitutions follow a 96-context profile (e.g. `data/signatures/PTA_artifact_SCAN2.txt`, the PTA artifact signature of SCAN2); `-A` stays the mean. Default data are unchanged. See manual 8.26.
- `--gain-sd S --gain-len L` (also `gain_sd`, `gain_len` in a configuration file; needs `-C`): amplification gain per haplotype and cell, a lognormal multiplier (mean 1, log-sd S) constant over segments of mean length L sites that multiplies the read depth of each allele: autocorrelated coverage and varying allelic imbalance. Continuous across pieces of a chromosome with `--ado-origin`/`--ado-seed`. Default data are unchanged. See manual 8.27.
- `--bam`, `--fastq`, `--read-len`, `--insert-mean`, `--insert-sd`, `--bulk-depth`, `--contig`, `--dup-mean` (also in a configuration file; need `-C`): read-level simulator. Paired-end reads (150 bp) of the amplified genome of every cell as BAM(+BAI) and FASTQ.gz, with molecules and PCR duplicates that share the errors of the amplification, gain, ADO blocks shaping the coverage; `ref.fa` and optional healthy `normal.bam`. `tools/bamcheck.py` checks the BAM files. Default data are unchanged. See manual 8.28.
- Read-level mode writes `reads_<n>/truth.vcf` (true genotype of every cell). `tools/benchmark.py`: `eval` (precision/recall of any caller VCF against the truth) and `pileup` (naive baseline on the BAM files, with and without PCR duplicates).
- `--blocks B`, `--fasta FILE`, `--region R`, `--germline-vcf FILE` (also in a configuration file): a chromosome in blocks inside the binary. One tree for all the blocks, one VCF with the positions of the chromosome, `summary.tsv` with a TOTAL row, `coverage.tsv` in chromosome coordinates, real reference (plain or gzip FASTA; N left out) and user germline SNVs (REF = reference base, flag GERMLINE). `tools/chrom.py` is now a wrapper of these options and writes the same files as before. Default data are unchanged. See manual 8.29.
- Checked: the 30 built-in signatures are identical to the COSMIC v2 table (`data/signatures/COSMIC_v2_SBS_GRCh37.txt`, test 2g38); signature 1 is 67.5% C>T in the profile (less in a simulation on a sequence with few CpG).
- The three modes (genotypes, read counts, reads) are now explicit: `--check` shows the mode, an option that the mode does not use is an error in reads mode (and without `--bam`/`--fastq` for the reads options) or a note in genotypes mode, and `-h` is organised by sections. Manual 4.2 has the table of options by mode. `--amplicon-len` and `--amplicon-cv` (unreleased) were removed: `--gain-sd/--gain-len` is the multiplier per haplotype and segment in both modes. `-F` and `-U` are described as older (`--config`, `--fasta`). Default data are unchanged.
