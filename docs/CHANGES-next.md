# Unreleased (after 2.2.7)

## Fixes
- `-T` (user tree): the number of cells is now the number of leaves of the tree, so `-s` no longer has to match it (before, a tree with more leaves than `-s` crashed).
- Branch lengths of the trees written with `-6` use `%.10g` instead of `%8.6f`, so very short branches are no longer rounded to 0 when the tree is reused with `-T`. (Only the text of the tree files changes; simulated data are identical.)
- User tree reader: a branch length shorter than the previous one no longer inherits leftover characters.
- `-T`: when `-s` differs from the number of leaves of the tree, a note says that `-s` is ignored (also shown by `--check`).

## New
- `--no-outgroup` (also `no_outgroup: true` in a configuration file): simulate the tumor only. The healthy outgroup cell is not in the tree file, the VCF/BCF, catg, pileup, genotype files or the statistics, and it does not decide whether a site is variable. The reference is still the healthy root genome (all 0), and the trunk (`-k`) is kept, so truncal mutations are still variants of every cell. The tree written with `-6` has the ingroup only, and `-T` reads it back as it is.
- `--min-alt-reads M` (also `min_alt_reads` in a configuration file): a site is called variable (VCF, catg, pileup...) only when some cell has a non-reference ML genotype supported by at least M reads of that allele (default 0: any non-reference call, as before). Unlike a filter on the number of cells, it keeps singletons, i.e. mutations in a single cell, which fix the terminal branch lengths. `--summary` has two new columns: `singleton_sites` (true variable sites with the non-reference allele in one cell only) and `singleton_recall` (fraction of them that are called variable).
- `--summary` has ten more columns, `inv_AA` ... `inv_TT`: number of sites that are not variable sites (not in the VCF) for each genotype of the healthy root. Together with the variable sites they add up to `-l`.
- `tools/chrom.py` (prototype): simulates a long chromosome by blocks of sites on one tree (generated once, tumor only), writes one VCF with the positions of the chromosome, and a summary table per block with the invariant counts. Example: `python3 tools/chrom.py --exe cellcoal --blocks 50 --block-size 200000 --out chr1 -- -s100 -u2.4e-8 -e10000 -g1e-4 -b1 -C10 -D0.25 -E0.001 --min-alt-reads 2`.
- `tools/chrom.py --fasta F --region chr:start-end`: the reference sequence of the chromosome comes from a standard FASTA (several lines, upper or lower case, optional `.fai`); sites that are not A, C, G or T (N) are left out of the simulation. VCF with the real CHROM and POS. Germline SNPs: either simulated (`-c`) or given with `--germline-vcf` (SNVs, phased or unphased), not both. At germline sites the VCF has the reference base as REF (genotypes renumbered) and the flag GERMLINE instead of SOMATIC.
- `--coverage W` (also `coverage_window` in a configuration file; needs `-C`): writes `coverage.tsv` with the mean read depth of every cell over the sites that are NOT variable sites (not in the VCF), in windows of W sites; `n_sites` is the number of such sites in the window. Together with the VCF it gives the depth of every cell at every site. `tools/chrom.py` writes `chrom_coverage.tsv` (BED-like, 0-based start, real coordinates, sites that are N are skipped) with `--coverage-window` (default 10000).
- Note (not a bug): the number of sites in the VCF differs by about 0.4% between dense and sparse genomes for the same seed, because ADO and genotyping errors use a different random stream in sparse mode (same distributions). Streamed reads (which use sparse genomes) equal stored reads with `CELLCOAL_SPARSE=1`, not the default dense stored reads. Large genomes (the block mode) always run sparse, so compare runs of the same kind.
- `tools/chrom.py` also writes one BED file per cell, `chrom_coverage_bed/<cell>.bed` (chrom, start, end, mean depth, n_sites), with the depth of the sites that are not in the VCF.
- `tools/chrom.py` uses `--min-alt-reads 2` by default (five 200 kb replicates, 100 cells, 10X, ADO 0.25: precision 0.70, recall 0.95, singleton recall 0.84; with 3: precision 1.00, singleton recall 0.76).
- `--min-alt-vaf F` (also `min_alt_vaf` in a configuration file): together with `--min-alt-reads`, the non-reference call of a cell has to be supported by at least a fraction F of the reads of that cell. With 100 cells, 10X, ADO 0.25, error 0.001 and `--min-alt-reads 2`, F=0.3 raises the precision from 0.72 to 0.97 and keeps 98% of the true sites (93% of the singletons) that `--min-alt-reads 2` keeps. `tools/chrom.py` now uses `--min-alt-reads 2 --min-alt-vaf 0.3` by default.
- `--ado-block L`, `--ado-origin O`, `--ado-seed S` (also `ado_block`, `ado_origin`, `ado_seed` in a configuration file): allelic dropout in contiguous segments (a two-state chain per allele and cell, lost segments of mean length L sites, same mean ADO as `-D`/`-P`). The segments continue across the pieces of a chromosome (`--ado-origin`, `--ado-seed`); `tools/chrom.py` passes them. Default data are unchanged. See manual 8.24.
- `--signature-file FILE` (also `signature_file` in a configuration file): 96-context signature profiles in COSMIC format used by `-S` instead of the 30 built-in ones. `data/signatures/` has COSMIC v3.6 SBS1 + SBS5 and the PTA artifact signature of SCAN2. Default data are unchanged. See manual 8.25.
- `--amp-signature FILE` (also `amp_signature` in a configuration file; needs `-C` and `-A`): the amplification error depends on the trinucleotide context and its substitutions follow a 96-context profile (e.g. `data/signatures/PTA_artifact_SCAN2.txt`, the PTA artifact signature of SCAN2); `-A` stays the mean. Default data are unchanged. See manual 8.26.
- `--gain-sd S --gain-len L` (also `gain_sd`, `gain_len` in a configuration file; needs `-C`): amplification gain per haplotype and cell, a lognormal multiplier (mean 1, log-sd S) constant over segments of mean length L sites that multiplies the read depth of each allele: autocorrelated coverage and varying allelic imbalance. Continuous across pieces of a chromosome with `--ado-origin`/`--ado-seed`. Default data are unchanged. See manual 8.27.
- `--bam`, `--fastq`, `--read-len`, `--insert-mean`, `--insert-sd`, `--amplicon-len`, `--amplicon-cv`, `--bulk-depth`, `--contig`, `--dup-mean` (also in a configuration file; need `-C`): read-level simulator. Paired-end reads (150 bp) of the amplified genome of every cell as BAM(+BAI) and FASTQ.gz, with molecules and PCR duplicates that share the errors of the amplification, gain, ADO blocks and amplicon structure shaping the coverage; `ref.fa` and optional healthy `normal.bam`. `tools/bamcheck.py` checks the BAM files. Default data are unchanged. See manual 8.28.
- Read-level mode writes `reads_<n>/truth.vcf` (true genotype of every cell). `tools/benchmark.py`: `eval` (precision/recall of any caller VCF against the truth) and `pileup` (naive baseline on the BAM files, with and without PCR duplicates).
- `--blocks B`, `--fasta FILE`, `--region R`, `--germline-vcf FILE` (also in a configuration file): a chromosome in blocks inside the binary. One tree for all the blocks, one VCF with the positions of the chromosome, `summary.tsv` with a TOTAL row, `coverage.tsv` in chromosome coordinates, real reference (plain or gzip FASTA; N left out) and user germline SNVs (REF = reference base, flag GERMLINE). `tools/chrom.py` is now a wrapper of these options and writes the same files as before. Default data are unchanged. See manual 8.29.
