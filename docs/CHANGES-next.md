# Unreleased (after 2.2.7)

## Fixes
- `-T` (user tree): the number of cells is now the number of leaves of the tree, so `-s` no longer has to match it (before, a tree with more leaves than `-s` crashed).
- Branch lengths of the trees written with `-6` use `%.10g` instead of `%8.6f`, so very short branches are no longer rounded to 0 when the tree is reused with `-T`. (Only the text of the tree files changes; simulated data are identical.)
- User tree reader: a branch length shorter than the previous one no longer inherits leftover characters.
- `-T`: when `-s` differs from the number of leaves of the tree, a note says that `-s` is ignored (also shown by `--check`).

## New
- `--no-outgroup` (also `no_outgroup: true` in a configuration file): simulate the tumor only. The healthy outgroup cell is not in the tree file, the VCF/BCF, catg, pileup, genotype files or the statistics, and it does not decide whether a site is variable. The reference is still the healthy root genome (all 0), and the trunk (`-k`) is kept, so truncal mutations are still variants of every cell. The tree written with `-6` has the ingroup only, and `-T` reads it back as it is.
- `--min-alt-reads M` (also `min_alt_reads` in a configuration file): a site is called variable (VCF, catg, pileup...) only when some cell has a non-reference ML genotype supported by at least M reads of that allele (default 0: any non-reference call, as before). Unlike a filter on the number of cells, it keeps singletons, i.e. mutations in a single cell, which fix the terminal branch lengths. `--summary` has two new columns: `singleton_sites` (true variable sites with the non-reference allele in one cell only) and `singleton_recall` (fraction of them that are called variable).
- `--summary` has ten more columns, `inv_AA` ... `inv_TT`: number of sites that are not variable sites (not in the VCF) for each genotype of the healthy root. Together with the variable sites they add up to `-l`.
- `tools/chrom.py` (prototype): simulates a long chromosome by blocks of sites on one tree (generated once, tumor only), writes one VCF with the positions of the chromosome, and a summary table per block with the invariant counts. Example: `python3 tools/chrom.py --exe cellcoal --blocks 50 --block-size 200000 --out chr1 -- -s100 -u2.4e-8 -e10000 -g1e-4 -b1 -C10 -D0.25 -E0.001 --min-alt-reads 2`.
- `tools/chrom.py --fasta F --region chr:start-end`: the reference sequence of the chromosome comes from a standard FASTA (several lines, upper or lower case, optional `.fai`); sites that are not A, C, G or T (N) are left out of the simulation. VCF with the real CHROM and POS. Germline SNPs: either simulated (`-c`) or given with `--germline-vcf` (SNVs, phased or unphased), not both. Known limitation: at a germline heterozygous site the VCF REF is the maternal allele, not necessarily the reference sequence base, and the site is labelled SOMATIC; to be fixed when blocks are built into the binary.
